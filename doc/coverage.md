## Hole triage

Every line and branch is covered. Only toggle points remain, and none of
them is behavior a bench could reach and does not: each is a bit that is
constant for every runtime input or a bit fixed by a parameter. Run
`tools/cov_summary.py --holes` for the full list.

**Excluded: elaboration-only constant functions.** Verilator instruments
function bodies, but these are called only to compute localparams, so they
never execute during simulation. `// verilator coverage_off` and
`coverage_on` comments around them keep them out of the count:

- `hdmi_cec.sv`: `width_of`, which sizes the counters from the timing
  parameters, and `osd_align` and `osd_count`, which left-align and count
  `OSD_NAME`;
- `hdmi_audio_src.sv`: `left_align`, `byte_sum` and `spd_body`, which build
  the SPD InfoFrame from the `SPD_*` parameters.

Keep any new constant function inside such a pair.

**Toggle, `hdmi_audio_src.sv` (480 points).**

- Values selected from constants by the runtime rate or depth: `acr_n` (35),
  `acr_smp` (9), `fs_code` (4), `wl_code` (3), `aif_sf` (2), `aif_pb2` (8),
  `aif_csum` (6). A bit that has the same value for 32, 44.1 and 48 kHz (or
  for all three depths) never changes; `acr_n[12]`, set in 6144, 6272 and
  4096, is an example.
- The channel status words `cs_l` and `cs_r` (69 each): the consumer L-PCM
  status is constant apart from its sample-rate and word-length fields, and
  those fields' common bits.
- `acr_sub` (69): SB0 is zero, the N bytes are the constants above, and the
  CTS byte's top nibble holds only bits 16-18.
- CTS bit 19, in `cts_counter` and `cts_value` (4): the longest ACR period,
  49 samples at the widest divider (8191 + 255/256 clocks), is 401,408
  clocks, under 2^19 = 524,288. The register is 20 bits because the packet
  field is.
- `aud_hdr` (41), `aud_subs` (56), `subs` (3): the Audio Sample Packet header
  is constant apart from B.0 (192 frames are 48 packets of 4, so an IEC block
  always starts in subpacket 0 and B.1-B.3 stay 0); U and V are always 0; the
  low byte of each 24-bit sample slot sits under the 16-bit input sample and is
  always 0.
- `header` (22): header bits that no packet type the source sends ever sets.
- `frame_counter[1:0]` (4): the counter steps by 4.
- `AVI_PB2` (9), `avi_body` (38): reserved zeros, the Active Format bits
  fixed by `AVI_AFD_VALID`/`AVI_AFD` (one value per elaboration; `tb_avi`
  elaborates three, so some bits rise in one instance but never fall), and
  the constant PB1, PB3 and PB4 bytes and the checksum bits they fix.
- `aif_body` (29): the constant Audio InfoFrame bytes, with `aif_pb2` and
  `aif_csum` above.

**Toggle, `hdmi_cec.sv` (198 points).**

- `txbuf[0]`-`txbuf[15]` (191): the transmit buffer only ever holds the three
  frames the core sends: `<Image View On>` and `<Active Source>`, built from
  the address parameters, and the `<Set OSD Name>` reply, built from
  `OSD_NAME`. With one name and one address per elaboration, every bit that
  differs between those frames toggles and the rest are fixed. Bit 7 of the
  name bytes is never set, because the name is ASCII.
- `txlen` (4) and `tx_eom_byte` (1): the frames are 2 blocks (`<Image View
  On>`), 4 (`<Active Source>`) and 2 plus the length of `OSD_NAME`, so these
  bits are fixed by that parameter.
- `uart_data[7]` (2): the dump sends only ASCII hex digits, spaces and
  newlines.

**Toggle, `hdmi_encoder.sv` (36 points).** `header` (22) is the same set of
header bits as in `hdmi_audio_src`, seen through the encoder. `subs` (14):
bits that are 0 in every packet the encoder benches carry: the U and V bits,
the zero low sample byte, and ACR SB0, plus the InfoFrame bytes that share
those positions and are constant in those benches.

**Toggle, `hdmi_channel.sv` (4 points).** `acc[0]` and `acc_next[0]`: every
symbol changes the running disparity by an even amount, so bit 0 of the
count is always 0.
